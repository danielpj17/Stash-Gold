# Building the shareable iOS Shortcut (one-time, by the app owner)

Stash can show every user an **Add to iPhone** button that installs a
ready-made Shortcut and prompts them for their own token. You have to author
that Shortcut once, by hand, on an iPhone or iPad.

## Why this can't be automated

Two Apple constraints, neither of which has a server-side workaround:

1. **Shortcut files must be signed to install.** Signing is only possible via
   the `shortcuts sign` CLI, which exists only on macOS. A Linux serverless
   function can't produce an installable `.shortcut`.
2. **There is no API for creating iCloud share links.** Those are generated by
   tapping Share inside the Shortcuts app.

So a per-user, pre-baked shortcut isn't possible. What *is* possible is one
shortcut, shared once, that asks each person for their own token at install
time — which is what the steps below produce.

---

## 1. Create the Shortcut

On your iPhone, open **Shortcuts** → **+**.

### Add: Text

Add a **Text** action. Paste your ingest URL:

```
https://YOUR-APP.vercel.app/api/ingest
```

Rename this action's variable to `API URL` (long-press → Rename). This is what
you'll attach the Import Question to in step 2 — Import Questions can only
target a value, so it needs to live in its own action.

> Use your real production URL. The **iOS Shortcut** box on `/new-expense`
> shows it in the manual setup block.

### Add: Text (again)

Add a second **Text** action containing just your token placeholder:

```
PASTE_YOUR_TOKEN_HERE
```

Rename it to `API Token`.

### Add: Ask for Input (amount)

- **Prompt:** `Amount`
- **Input Type:** Number

Rename the result to `Amount`.

### Add: Ask for Input (description)

- **Prompt:** `What for?`
- **Input Type:** Text

Rename the result to `Description`.

### Add: Choose from Menu (category)

Add **Choose from Menu** and add one item per category you use — Groceries,
Eating Out, Gas, and so on. Inside each menu branch, add a **Text** action
containing that category's exact name.

> The names must match `EXPENSE_CATEGORIES` in `lib/constants.ts` exactly.
> A category the app doesn't know still saves, it just won't group correctly
> on the budget page.

Rename the menu result to `Category`.

### Add: Get Contents of URL

This is the action that actually posts.

- **URL:** the `API URL` variable
- **Method:** `POST`
- **Headers:**
  - `Authorization` → `Bearer ` followed by the `API Token` variable
    (type the word `Bearer`, a space, then insert the variable)
  - `Content-Type` → `application/json`
- **Request Body:** `JSON`, with these fields:

| Key | Type | Value |
|---|---|---|
| `expenseType` | Text | the `Category` variable |
| `amount` | Number | the `Amount` variable |
| `description` | Text | the `Description` variable |

Optional extras the API accepts:

| Key | Value |
|---|---|
| `account` | a `financial_accounts.id` — makes the expense move that balance |
| `date` | `YYYY-MM-DD` — back-dates the entry (defaults to now) |

### Add: Show Notification

So you get confirmation it worked. Something like `Logged $[Amount]`.

---

## 2. Add the Import Questions

This is the part that makes one link work for everybody.

Tap the Shortcut's **settings** (ⓘ or the sliders icon) → **Import Questions**
→ **Add Question**.

- **Question:** `Paste your Stash token`
- **Parameter:** the `API Token` text action

Add a second question if you'd rather not bake your URL in (useful if you ever
move domains):

- **Question:** `Your Stash URL`
- **Parameter:** the `API URL` text action

On install, iOS prompts for each of these and substitutes the answer. Nothing
personal is embedded in the shared shortcut itself.

---

## 3. Test it before sharing

Run the Shortcut on your own phone with your own token. Then check:

- The expense appears on the Expenses page.
- In the **iOS Shortcut** box on `/new-expense`, that token's **last used**
  date updates to today.

If you get a 401, the token is wrong or revoked. If you get 503, the server
can't reach the database.

---

## 4. Share it

Shortcut settings → **Share** → **Copy iCloud Link**.

Set that link as an environment variable:

```
NEXT_PUBLIC_SHORTCUT_ICLOUD_URL=https://www.icloud.com/shortcuts/xxxxxxxx
```

Add it locally in `.env.local` and on Vercel (Production, and Preview if you
use it), then redeploy.

> It must keep the `NEXT_PUBLIC_` prefix — it's read in a client component and
> is inlined at build time, so **a change requires a rebuild, not just a
> restart**. It's a public link by design; there's nothing secret in it.

The **iOS Shortcut** box on `/new-expense` will now show **Add to iPhone** for
every user, with the manual instructions demoted to "Or build it by hand".

---

## What a new person does

1. Sign in, go to **New Expense** and open the **iOS Shortcut** box
2. **New token** → copy it
3. **Add to iPhone** → **Add Shortcut** → paste the token when asked

Then add the Shortcut to their home screen or Back Tap for one-tap logging.

## If someone loses their phone

Revoke that token in the **iOS Shortcut** box on `/new-expense`. It stops
working immediately — no redeploy,
and nobody else is affected. Issue a new one and re-install the Shortcut.
